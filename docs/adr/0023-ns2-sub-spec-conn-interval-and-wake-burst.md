# 0023 — NS2 手柄链路采用亚规范连接间隔与显式唤醒广播

- 状态: active
- 日期: 2026-09-14
- 替代: 无

## 背景

NS2 主机把连接压到 5 ms（4 单位，低于 BLE 规范 7.5 ms 下限），广播厂商数据的状态位是主机唯一的唤醒判据，
0x09 报文的运动数据长度字节在主机开启 IMU 特性位后必须非零。原实现在连接后主动请求 >= 7.5 ms 间隔、
把回连广播写成 0x81、且运动长度填 0；实机排查「已连接但按键无反应」时最初的怀疑是间隔谈不下来，
验证后推翻了这个单因解释。

## 决策

五项一并落定：一是连接间隔交给主机，固件不主动请求参数，ESP32-S3 控制器由 CONFIG_BT_CTRL_BLE_MIN_CONN_INTERVAL_ENABLE（显式写入 sdkconfig.defaults，最低 3.75 ms）允许亚规范间隔，固件只在 GAP 连接更新事件里观测并把 itvl 暴露到串口 link；二是广播状态位按真机语义分离，发现/回连恒 0x00、唤醒突发才 0x81（窗口 10 秒：主机扫描窗口远长于真机 2 秒突发，太短会错过；已配对设备上电也先开一段窗口），突发由显式动作触发（调试页「唤醒 HOME」、串口 wake），广播载荷由 target/ns2/ns2_adv.c 统一成型并加黄金字节用例；三是 0x09 报文的 0x0E 固定填 0x28（40 字节），运动块以全零占位；四是**输入报文被采用的门槛是 0x0C/0x04（启用特性）而非间隔**——已验证实现（zhantss/ESP32-BLE5-NSController-Emulator）把整个上报流押在这条命令上（DEV_READY），实测 itvl=4 但未收到 0x0C/0x04 的链路按键同样无效，握把/顺序页的快捷回连正是这种形态，固件对齐为输入通知只在收到 0x0C/0x04 后发送，并配休眠看门狗：已订阅 15 秒仍未启用的会话断开并唤醒突发重连（每次上电至多 3 次）；五是**上报节奏 15 ms**（dp 仍 5 ms 采样、DP_SEND_DIV=3 分频，对齐已验证实现的 HID_REPORT_INTERVAL=15ms）——以 5 ms 从任务侧灌 63B 通知会打爆 NimBLE 发送队列，实测近半数通知因 mbuf 耗尽被丢、报文计数器跳号，主机不采用残缺流；15 ms 下实测零发送失败、按键立即可见。

## 考虑的方案

- 直接给 ESP-IDF 控制器归档打二进制补丁：S3 的控制器代码含 ROM 部分、补丁面不可控，且随 IDF 版本失效
- 继续请求主机接受 >= 7.5 ms 间隔（原实现）：与主机自己的下发方向相反，NimBLE 主机侧也按规范拒绝主动请求
- 保留回连广播的 0x81 状态位：真机抓包不支持，主机在待机中会被每一次回连广播唤醒
- 按逐连接事件 200 Hz 上报（真机形态）：任务侧无法与连接事件同步，实测打爆发送队列；15 ms 已被主机正常采用
- 以连接间隔为休眠判据（第一版看门狗）：会误杀已被 0x0C/0x04 完整启用、只是间隔停留在高位的会话，改为按特性启用判定

## 影响

- 实机验收：配对或主机回连后主机下发 0x0C/0x04，link 的 feat=1、itvl=4、txf=0，注入按键主机可见；
  醒着的主机不理会单方面唤醒广播与 0x00 回连广播，可靠入口是握把/顺序页（快捷回连僵尸由看门狗自动清理）。
- 开机自动回连在本条的形态下仍不可靠，由后续 ADR 取代解决。
- 运动块是零值占位：依赖体感的功能不可用，接入 IMU 后只需替换该块的数据来源。
- 亚规范间隔下单个连接事件时间很短：不应同时放大 ATT MTU 与 DLE，出现丢帧时优先降低 MTU。
