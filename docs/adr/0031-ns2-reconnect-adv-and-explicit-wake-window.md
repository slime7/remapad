# 0031 — NS2 常态广播回到回连形态，唤醒收成显式窗口

- 状态: active
- 日期: 2026-09-15
- 替代: 0024

## 背景

用户实机反馈两件事：设备通电且未连接时，休眠中的主机一进待机就被常态 0x81 广播叫醒（ADR 0024 已知并接受过的副作用，现在不接受）；
调试页「唤醒 HOME」在已连接时按下去先断链再重连，与实体手柄「醒着当主页键、睡下当唤醒键」的行为不符。
实机对账推翻了 0024 的前置结论：带正确主机地址的 0x00 回连形态在主机停在握把/顺序页、停在首页、
以及用电源键从待机醒来三种情况下都被采纳并自动连回，休眠中的主机则纹丝不动。

## 决策

常态（已配对、未连接）广播改成 0x00 回连形态并常驻：它不叫醒休眠中的主机，醒着的主机会自己连回来，开机自动回连不再依赖唤醒形态。0x81 唤醒形态只在「唤醒窗口」内发（窗口 10 秒，沿用 ADR 0023 的取值）：窗口由显式唤醒请求打开（调试页 HOME 在未连接时、串口 wake），主机连上或窗口到期即关闭，链路随后断开时广播已经回落成回连形态。调试页 HOME 按实体手柄语义分流——主机已注册会话时注入主页键，未连接时转成唤醒请求，按钮文案跟着状态走（HOME / 唤醒 HOME）。串口 adv 从 wake|reconnect 改成 auto|wake|reconnect：auto 按唤醒窗口决策（默认），另两个只作实机 A/B 对账。唤醒窗口与常态形态的判定在 ns2_adv 里做成纯函数并由固件主机端用例钉住。调试页的「配对 L+R」按键删除（CLI 的 key lr 一并删除）：Grip/顺序页不再是配对入口，JoyCon 组合未配对期间由固件自动注入 L+R，手动注入没有使用场景。

## 考虑的方案

- 保留 ADR 0024 的常驻 0x81：主机一进待机就被叫醒，用户明确不接受
- 断开后完全停发广播、等主机自己找回来：观察到的回连都是主机对我们广播的响应，醒着的主机不会主动来连，开机自动回连失效
- 用主机下发的 0x03/0x01（开启 BLE 唤醒广播）当窗口触发器：实机日志里主机从未下发过这条命令，只有设备自己的 resume 行
- 周期性发短 0x81 脉冲探测主机是否醒着：脉冲本身就会把休眠主机叫醒，与目标矛盾
- 常态静默、只在用户操作设备时才发唤醒形态（纯实体手柄形态）：主机醒着时也连不上，丢掉已验收的「开机自动回连」

## 影响

- 实机验收：主机睡下后不再被叫醒；用电源键唤醒主机后它自己连回设备；主机停在首页时设备重启仍能自动回连；调试页 HOME 在线时按主页键、离线时开窗口把主机叫起来。
- 唤醒窗口是唯一的叫醒路径：未连接时按调试页 HOME 或发串口 `wake`。
- 配对页的 L+R 兜底按钮保留。
