# 0064 — MCP 按键回放采用 TAS 式逐帧记录与单任务打断模型

- 状态: active
- 日期: 2026-10-01
- 替代: 无

## 背景

agent 与自动化要把编排好的按键序列存成文件复用重放，而 remapad_script 是一次性内联时间线、阻塞到放完。
长记录期间占住调用、没法观测也没法中止；回放线程与按键工具并发写同一按键引擎还会互相踩踏状态。

## 决策

回放做成 MCP 侧的文件回放：TAS 式逐帧状态记录，头部 frame_ms / fps 定帧长，帧行声明自该帧起保持的按键与摇杆态。
回放后台单任务执行、立即返回，进度进 remapad_status。
回放期间按键类工具与再次启动一律拒绝，打断只走 remapad_replay_stop（disconnect 兜底）。
结束、打断与循环边界都全松按键并回中摇杆。

## 考虑的方案

- 复用 remapad_script 的绝对毫秒动作表做文件格式：程序生成方便，但手写与录制对账困难，也没有 TAS 习惯的帧语义。
- 阻塞式回放（放完才返回）：实现最省，但长记录期间 agent 失去观测与打断能力。
- 直接兼容 BizHawk / fm2 等既有 TAS 格式：键名面与摇杆刻度都是本项目私有，字节级兼容收益低、解析负担反而更重。

## 影响

- 按键记录文件成为可入库、可复用的测试资产；单任务模型免去并发编排的状态组合。
- 打断响应按 20ms 时间线切片理解，注入时值精度仍是 ±10ms 量级；帧长只是时间刻度，不追求与游戏帧严格对齐。
