# 0035 — NS2 耳机状态按输入设备的 3.5mm 状态透传

- 状态: active
- 日期: 2026-09-15
- 替代: 无

## 背景

GATT 里早就声明了耳机音频下行（0x002C）与麦克风上行（0x002E）两个特征，但它们的写入只留日志；0x09 报文的耳机音频状态字节（偏移 0x0D）与 0x05 的耳机插入位写死为 0，私有格式里的 mic_level / mic_muted 也没有任何布局行填充。结果是 PC 手柄插着 3.5 mm 耳机时，主机侧永远显示未插入，走耳机的那条音频通路也不会有数据下发。

## 决策

把耳机状态纳入私有格式与 NS2 编码的单一来源：pad_state 增加 headset_present / headset_mic（受 PAD_CAP_MIC 门控），布局行增加 headset_off 与读法标记 PAD_HEADSET_PS（单字节，bit0 插入、bit1 带麦），解析与电量、触摸同一处；ns2_output 持有最终取值（auto 时由目标侧按输入设备派生成 0x00 / 0x05，串口 headset 0xNN 可钉住覆盖值），编码路径与同代透传路径都从它取，非 0 时一并置 0x05 的耳机插入位。偏移未登记（PAD_OFF_NONE）的行保持未插入，不猜偏移。

DualSense 蓝牙行（0x31）的第 55 字节已按 DualSense Edge 插拔差分核对并登记（0x00 拔掉 / 0x01 插入 / 0x03 插入带麦）；带麦位不进派生值——主机接受 0x05 与 0x0D，但换上 0x07 / 0x0F 后约 150 ms 就取消 0x000E 的订阅，输入不再被采用。

## 考虑的方案

- 写死一个非零值让主机看到耳机（否决：主机会开始往 0x002C 推音频，而设备眼下不消费，等于伪造一个不存在的通路）
- 一步到位转发主机下发的耳机音频流（暂缓：0x002C 的流格式没有公开资料，要先抓包定协议，本轮先把状态与前提做对）
- 只保留串口手动置位、不从输入设备派生（否决：与真实插拔脱节，验收时说明不了问题）

## 影响

- 正面：耳机状态跟着手柄的真实插拔走，主机侧的耳机指示与音频通路前提成立；派生值与覆盖值同源，0x09 与 0x05 不会各写一个数。
- 顺带修掉合成路径的字段漏拷：私有格式合成只拷主源字段，新增字段漏拷会静默停在默认值上，主机端用例逐个钉住。
- 约束：主机认「插入」但拒绝「带麦」，带麦那一档要能被接受，前提是 0x002C 上的音频 / 麦克风通路先落地；
  DS4 与 DS5 有线行的耳机字节仍未核对，核对方法与状态见 [controller-ps.md](../controller-ps.md)。
- 后续：状态一旦被主机接受，0x002C 上可能出现音频数据，届时再评估是否把该流经桥接转发到 PC。
