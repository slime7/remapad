# 0055 — core 与屏幕 UI 分离，界面成为可选装配

- 状态: active
- 日期: 2026-09-24
- 替代: 无

## 背景

固件核心（USB/BLE/NS2/设置）与屏幕 UI 实现耦合在同一棵源码树里：
控制面命令队列靠界面任务泵、面板初始化住在界面任务里，没有界面框架工具链就连不出固件。
目标是 ui/ 之外零界面框架依赖：固件核心只认一份 C 契约，界面组件按需编入。

## 决策

固件核心持有 ui_service.h 契约：状态快照装配、动作分发与生命周期入口，实现按链接期选择（ui/slint_ui 组件或 main/ui/ui_stub.c 空实现）。
控制面命令队列改由 js_bridge_service_start 建的独立服务任务泵，不再依赖界面任务。
界面源码、固件界面组件与两份 build.rs 共用的编译口径全部收进 ui/ Cargo 工作区，固件经 EXTRA_COMPONENT_DIRS 引入组件。
REMAPAD_UI 构建开关（默认 ON）关闭时纯 C 可编译且不需要 Rust 工具链：面板/触摸/背光不初始化，设置经 PC 串口 CLI 控制。
ui/ 之外的文档与注释用「屏幕 UI」称呼界面层，不提具体框架。

## 考虑的方案

- 保持界面常编入，只把源码挪进 ui/：构建门槛不变，满足不了无界面框架可编译的目标。
- core 契约 + 链接期选择提供者 + CMake 开关：核心零界面依赖，无 UI 构建仍是完整固件（选定）。
- 用 Kconfig 隐藏开关替代 CMake 变量：开关要进 menuconfig 树，对目录级装配不如 CMake 变量直白。

## 影响

- 无 UI 构建里 shot 与渲染诊断命令不可用，串口回提示；实机截图只在带 UI 构建可用。
- 命令的执行上下文从界面任务移到控制面服务任务：两者本就经队列交接，实机回归重点看 PWR 键与串口命令时序。
- 状态快照结构定义在核心契约头，ui/slint_ui 的 Rust 镜像与 C 头两侧同步的义务不变。
