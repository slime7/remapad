# 0026 — 手柄输入按同代透传、异代解析的规则分发

- 状态: active
- 日期: 2026-09-15
- 替代: 无

## 背景

桥接与 USB host 两条输入路径现在都能收到 Nintendo 系手柄报告：真 Switch 2 手柄的报文体与 NS2 主机要的语言完全一致，先解析成私有格式再重编码会丢掉公开资料里未解析的 40 字节运动块与真电量；Switch 一代手柄的报告格式与 NS2 目标不同，必须解析后重编码。此前没有规则说明什么条件下可以原样转发。

## 决策

布局行声明设备自带的报告语言（native_lang：none / NS1 / NS2）与期望身份，目标声明自己的语言。target_send_pad 在「设备语言等于目标语言、且报告格式与身份都对得上」时把设备报文体原样交给目标发送，只重写 0x09 的状态字节（特性标志、NFC、耳机）；否则走解析重编码。串口 CLI 的 relay 0|1 关闭透传，便于实机 A/B。

## 考虑的方案

- 同代透传、异代解析（采纳）
- 全部解析重编码（否决：0x09 运动块结构未公开，真机陀螺仪与真电量会在重编码中丢失）
- 全部原样转发（否决：NS1 报告与 NS2 目标格式不同，转到主机是无效报文）

## 影响

- 正面：真 NS2 手柄的按键、摇杆、真电量与真运动数据直达主机；解析与映射仍只有一份，异代手柄走同一条三段通路。
- 约束：透传载荷与设备语言进入私有格式；新增设备语言时必须同时声明期望身份，否则会被身份条件挡下并回落到解析路径。
- 反馈方向同理：NS2 手柄直接吃主机的 32 字节 LRA 参数包，其余家族按布局行的输出描述编码。
