# 0029 — 手柄操控屏幕的方向键分工：上下走页面内容、左右切底栏

- 状态: superseded
- 日期: 2026-09-15
- 替代: 无

## 背景

手柄操控模式（ADR 0028）落地时方向键只有一份「显示顺序」清单：页面控件在前、底栏在后，上下左右都在同一份清单里挪。实机上用起来有两处不对：横向的底栏挂在纵向列表末尾，从内容切到「设置」要把整页走一遍；页面滚到下方后焦点停在最后一项，最后一段内容（系统页的设备信息卡）再也滚不到。

## 决策

方向键分两个轴：上下在页面内容里按显示顺序走，焦点已经在最后一项时再按下，页面自己继续往下滚到页底；左右只在悬浮底栏两项之间走——从内容按左右时焦点落到方向对应那一端的底栏键，已经在底栏时夹在两端。实机上单独按住 L1 / R1 与按左 / 右等价（组合键本身以 L1 + R1 起手，因此四键同按的进出那一刻与两肩键同按都不发方向）。实现落在 UI 层（hooks/usePadControl.ts）：用框架的 pushFocusController 在页面容器与悬浮底栏各注册一个控制器，焦点在哪棵子树里就由谁接管方向键；焦点行被「额外下移」推出可视带后，跟随滚动让位到焦点换人为止，滚到页底的过程才不会被拉回。这条细化 0028 的方向键语义，组合键判定、捕获期间的中性上报与退出路径仍以 0028 为准。

## 考虑的方案

- 左右直接切页、不落到焦点环上（否决）：底栏两枚按钮就再也拿不到焦点，「方向键聚焦、圆圈键确认」在底栏上出现例外，手柄与触摸成了两条不等价的路径
- 页面内按几何位置做二维移动（否决）：页面控件都是单列列表，能带来差别的只有并排两键（系统页背光 −/+、调试页 a/home），却要为每个页面维护一份几何表；方向键因此只表达显示顺序
- 肩键复用为第二组左右键（采纳）：底栏是横向的，肩键是最顺手的横向按键，切底栏不必把拇指挪回十字键
- 进模式那一刻照原样转发肩键（否决）：四键同按进模式，底栏选中项会立刻被自己挪走一格；改为组合键全按下或两肩键同按时不发方向

## 影响

- 正面：底栏切换有两条等价路径（左右键与实机肩键）；焦点停在最后一项后页面还能继续往下滚，页底的信息块不用再靠触摸拖出来。
- 正面：不插手柄也能验证——`key l` / `key r` 与 `key left` / `key right` 走同一位，调试页也有入口，浏览器预览与实机共用同一条焦点通路。
- 约束：焦点行被「额外下移」推出可视带后，跟随滚动要让位到焦点换人为止——此时再按上/下或切页，跟随滚动会把焦点行重新拉回可视带。
- 约束：页面里并排的两个可聚焦控件在上下遍历里是相邻项，按上下会横着走一格（系统页背光 −/+、调试页 a/home）；屏幕没有横向定位，方向键表达的是显示顺序。
