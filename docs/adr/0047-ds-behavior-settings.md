# 0047 — DS4/DS5 手柄行为设置（触摸板映射加减键与截图键）

- 状态: active
- 日期: 2026-09-21
- 替代: 无

## 背景

DS4 与 DualSense 的触摸板按下在私有格式里落在分享位（PAD_BTN_SHARE），目标侧作截图。
触摸板位置一直没有被消费：解析只读第一个触点、按每点 3 字节登记，而 Linux hid-playstation.c 里两家都是每点 4 字节
（触点字节 + 12 位 X + 12 位 Y），DS4 行的偏移还差一个字节。
手柄侧却已经缺了直接按出减号与加号的位置——触摸板比 SHARE / Options 两颗小键好按，用户想拿它当加减键用。

## 决策

新增两项持久化设置（触摸板映射加减键默认关、截图键默认开），落在「DS4、DS5 设置」页与串口 CLI 的 ds 命令上，
由数据面每拍按配置改写触摸板按下的键位：位置可用时按先触发的半区发减号（左半）或加号（右半），
位置取不到时退回截图键开关那一档，键位在按下那一刻定一次、按住期间不变。
跨采样状态（触点触发先后的比较与按下期间的锁存）由新的 pad/ds_behavior.c 承担，数据面只在采样后调用一次。
触摸点解析改为按 4 字节读一帧里的两个触点，按归一后的 X 分到左右半区。

## 考虑的方案

- 把映射做进目标编码器（ns2_target）：目标只认私有格式，设置会绑死在 NS2 上，新增目标要再实现一遍。
- 在解析层（pad_device）直接改键位：解析是每帧纯函数，判断「先触发」需要跨帧状态，塞进去会破坏它的无状态契约。
- 新增 pad/ds_behavior.c 承接跨采样状态、在数据面每拍改写键位（采纳）。
- 触摸点沿用 3 字节解析并只读第一个触点：与 Linux hid-playstation.c 的 4 字节触点不符，位置整体错位一个字节。
- 用触点 ID 认「先触发」：ID 由手柄自己轮转，同一根手指的 ID 会变，跨帧比较不可靠；改用「这一路从无到有」的采样时刻。

## 影响

- DS4 有线/蓝牙与 DualSense 有线/蓝牙四个布局行都登记了触摸点偏移与量程（DS4 在 35/37、DS5 在 33/34，每点 4 字节），
  DS5 两行补上 PAD_CAP_TOUCHPAD；偏移取自 Linux 驱动的报告结构，实机抓包核对前仍是初值。
- 触摸板按左右半区建模：一帧两个触点按归一后的 X 分到 touch[PAD_TOUCH_LEFT] / touch[PAD_TOUCH_RIGHT]，
  同一半区保留先出现的那一路，半区边界取归一闪量程的中点，归一值夹进 0-4095。
- 设置只在 PS 家族（DS4 / DS5）的触摸板按下位上生效，Xbox Series 的分享键与 NS 手柄的触摸板位不受影响。
- 设置页是四叶草第 5 页（系统信息页之前），开关是 components/Switch（轨道 + 滑块两个节点）；
  串口 CLI 新增 ds touchpad|capture on|off，没有 UI 时也能验证。
- 两处触摸点偏移都要用 pc/remapadctl.py --dump 抓包复核，方向反了会表现为左右半区颠倒。
- 触摸板映射开着而这一帧没有触摸数据时，键位退回截图键开关那一档——位置未知不猜半区。
