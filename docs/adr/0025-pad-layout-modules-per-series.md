# 0025 — 家族布局按系列分文件登记，注册表统一匹配

- 状态: active
- 日期: 2026-09-15
- 替代: 无

## 背景

家族表原先是 pad_device.c 里的一张长表：布局行、按键位图、解析逻辑与兜底声明混在一个文件里，PS 系三种型号接入后表已跨四种布局，新增一个系列要在同一文件里翻找插入位置，同一系列的两种连接（例如 DualSense 的有线与蓝牙）也容易被拆散。

## 决策

pad/ 下拆出布局契约与注册表：layout.h 定义布局行 pad_layout_t 与模块 pad_layout_module_t，layout.c 持有共用按键位图、模块清单与匹配逻辑（按家族、Report ID、连接方式、PID 逐行筛选），各系列的布局行放 layouts/ 下一个文件一个系列（xbox / ds3 / ds4 / ds5），同一系列的有线与蓝牙行同处一个文件；pad_device.c 只保留解析与归一。加一个系列＝加一个文件并在 layout.c 的模块表里登记一行。

## 考虑的方案

- 布局按系列分文件＋注册表匹配（采纳）
- 维持单文件长表（否决：跨系列的行混在一起，新增系列要改同一文件，跨连接的同一系列容易分散）
- 按连接方式分文件，有线与蓝牙各一份（否决：同一系列的两种连接只差前缀与偏移，分开后无法就近对照，改动要跨文件同步）

## 影响

- 正面：一个系列的范围就是一屏代码，加系列只加文件与一行登记；同一系列的多种连接就近对照；共享按键位图与解析逻辑各只有一份。
- 约束：匹配顺序由注册表的模块表决定，同一组合多行时取先出现的那个；新增模块要同步固件与主机端测试的源码列表。
