# 0014 — 页面按需挂载并逐帧自顶向下填充

- 状态: superseded
- 日期: 2026-09-13
- 替代: 0013

## 背景

首帧只挂首页、其余页面每帧补挂的方案（ADR 0013）把首帧压到 10.1 秒，但首帧后仍有 8-9 秒后台建树：每帧阻塞 0.6-2.4 秒，首页加载 spinner 在这段时间里几乎转不动，用户即使在首页也能感到整机卡顿。实机与预览实测原生建树成本约每个节点 50 ms（240x280），且成本集中在 Vue Vapor 的逐节点微 DOM 挂载，不在宿主 op（全程 114 ms）、样式解析、GC 或 CPU。

## 决策

其余页面改为按需挂载：首次进入某页时才建外层容器，页面内部用 useMountCursor 每帧放行一个填充块，块序与视觉顺序一致（外层容器 -> 各块自上而下）。切页只翻转 hidden，已建页面不再重建；首页也在根节点上翻转 hidden（外层页面容器层因此删除，每页省一层节点）。填充期间首页留白处仍显示加载提示。

## 考虑的方案

- 按需挂载 + 逐帧自顶向下填充（选定）：首次进入付出该页建树成本，但分块后单帧阻塞降到数百毫秒，页面逐块出现
- 全部页面首帧一次性挂载：首帧 18.4 秒，不可接受
- 首帧后每帧补挂一页（ADR 0013）：首页 2 秒可见，但后台 8-9 秒持续阻塞，spinner 与触摸反馈都受影响
- 框架 Lazy 组件的 reveal 分批放行：无法在切页时插队，且页面未挂载前无法写入 hidden
- 预建节点但不设属性：属性设置只占 1% 成本，收益可忽略

## 影响

- 首帧只建壳、状态栏、底栏与首页，首页约 2 秒可见，页面从首帧起就可交互
- 每个填充块约 5 个节点（约 250 ms），页面自上而下逐块出现，切页后能看到明确的推进过程
- 外观与 ADR 0013 版本逐像素一致（预览 9 张截图 0 差异），节点数净减约 15 个（页面容器层 7、导航覆盖层 2、状态栏占位 1、信息行占位 5）
- 新增页面必须在 App.tsx 的 mountedTabs 分支登记，并在页内调用 useMountCursor 分块；外层容器层不再提供 hidden 切换，页面根节点必须自己翻转 hidden
- 页面首次进入时的建树阻塞仍然存在（分块后单块数百毫秒），进入页面瞬间的触摸响应会延迟一块的时间
