# 0030 — NS2 唤醒广播携带主机最近一次连接的地址

- 状态: active
- 日期: 2026-09-15
- 替代: 0024

## 背景

ADR 0024 把已配对身份的常态广播定为「0x81 加凭证里的主机地址」，但开机自动回连在实机上没有生效：板卡重启后 45 秒内主机没有任何连接动作，只有进握把页并按下设备配对键才连得上。对照同一台主机的连接记录发现，配对交换（0x15/0x01）给的是两条只差一位的地址（本设备实测末字节 0x8c 与 0x8d）：凭证里存的那条发出去主机不理，而主机连接时在用的那条（末字节 0x8d）能让主机在板卡重启后自己连回来。

## 决策

回连与唤醒广播携带的主机地址改为「最近一次 NS2 会话记录到的对端地址」：它只在连接对端命中凭证的连接事件与配对交换完成时写入，普通 BLE 主机（PC / 手机）的连接不会污染它；没有记录时回退到由新到旧第一条非全零凭证地址，两者都没有可用地址就退化为发现广播。挑选规则做成纯函数 ns2_adv_choose_host_mac() 并由固件主机端用例钉住。本条只取代 ADR 0024 里「唤醒广播携带凭证地址」这一项，广播形态（已配对身份常驻 0x81 唤醒）与配对键语义不变。

## 考虑的方案

- 继续用凭证里的主机地址（维持 0024 原文）：实测主机不采纳，开机自动回连仍然失败
- 两条地址轮换广播（或同时占两个广播实例）：主机只认自己在用的那条，轮换只会把回连时机拖长，真机也不是这么发的
- 不带地址改发发现广播：主机醒着时不采纳，用户仍需进握把页并按下配对键

## 影响

- 实机验收：主机停在首页时板卡重启即自动回连、不需要碰主机或设备（2026-09-15 实测：唤醒广播载荷状态位 0x81、地址 8d:63:27:70:68:b8，重启后主机自行连回，link 显示 feat=1、输入被采用）。配好但还没连过时只有凭证地址可用，首次仍可能连不上；连过一次后记录值生效并自动纠正。凭证地址保留为兜底，换主机重新配对的路径不受影响。
