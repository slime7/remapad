# 0021 — 输入通路按接收 / 处理 / 转换三段分层

- 状态: active
- 日期: 2026-09-14
- 替代: 0011

## 背景

输入通路在 PC 桥接落地与多家族手柄接入时暴露出分层缺失：输入源直接填 NS2 状态，家族差异（报告布局、量程、按键物理位置）与目标差异（NS2 Pro / JoyCon2 的键集与数字扳机，将来还有 NS1）混在同一段代码里，每加一种手柄或一个目标都要重复改动；PC 桥接又引入一条与串口 CLI 共用 USB-Serial/JTAG 的高频输入流，需要独立的接收与分帧层。ADR 0011 的 ns2/ble/dp/usb 目录划分已不足以表达这三段职责。

## 决策

firmware/main/ 下按三段划分输入通路：pad/（处理段：私有格式 pad_state_t 与家族布局表，按家族 / Report ID / 连接方式登记字段偏移，负责按键按位置语义映射、摇杆归一并套死区、扳机保留模拟量、能力位标注）、input/（接收段：桥接帧协议与解帧状态机、USB-Serial/JTAG 的唯一读取者、实现 dp_source_t 的桥接输入源，非帧字节交回 CLI 行解析）、target/（转换段：目标编码器接口 pad_target_t，现有 ns2/ 编码迁入 target/ns2/，Pro 与 JoyCon2 共用一份实现，扳机数字化阈值作为目标内常量）。数据流固定为 input → pad → target → 目标输出通道，dp_source_t 的采样类型改为 pad_state_t。

## 考虑的方案

- 三段分层：input/ 收字节与设备标识、pad/ 解析并归一成私有格式、target/ 编码成目标报文（采纳）
- 维持输入源直填 NS2 状态，家族差异写进编码器分支（否决：每加一种手柄都要改编码器，PC 桥接与 USB host 直插无法共用同一份解析）
- PC 侧完成解析并直接下发目标报文（否决：家族表与映射会在 PC 与固件各存一份，USB host 直插无法复用，协议事实被拆到两处）

## 影响

- 正面：新增手柄只加家族表一行，新增目标（如 NS1）只加一个 `pad_target_t` 实现；解析与映射在固件只有一份，
  桥接 PC 与 USB host 直插共用；CLI 文本与桥接帧共用一根 USB-Serial/JTAG，桥接不再需要独占端口。
- 约束：家族表偏移初值取自公开资料，需用 `--dump` 实测回填后再固化；私有格式是全量模型（含 IMU、触摸板、麦克风、设备电量），
  目标只消费自己能力范围内的字段，其余在能力位变化时提示一次。
- 本 ADR 部分取代 0011 的目录划分；0011 的数据面汇合约定继续生效，0011 状态保持 active。
