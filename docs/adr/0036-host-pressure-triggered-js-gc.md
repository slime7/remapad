# 0036 — JS 堆的显式 GC 由宿主按 PSRAM 压力触发

- 状态: active
- 日期: 2026-09-16
- 替代: 无

## 背景

QuickJS 的阈值式 GC 每触发一次就把阈值抬到存活堆的 1.5 倍。
bundle eval 之后 JS 堆常驻约 3.8MB，阈值从此高于常规存活量，引擎 GC 实际不再触发。
Vue Vapor 响应式链路的环垃圾在两次 GC 之间持续累积，最终把物理 PSRAM 顶满，ui_core 分配失败而 abort 重启。
guest 的 JS 分配与 ui_core 原生分配都走 PSRAM 优先分配器，8MB PSRAM 是唯一上限。

## 决策

宿主在 owner task 帧循环里按压力触发显式 GC：每帧读一次 PSRAM 余量，比上次回收基线跌过 256 KiB 就 JS_RunGC 一次，并把基线钉回回收后的水位，余量回升则基线跟随上抬。
触发时打一行对账日志（跌幅与回收量）。
方式与上游 PocketJS PSP host 的 arena-pressure GC 同构（hosts/psp/src/main.rs）。
60 秒一行的内存对照诊断日志保留。

## 考虑的方案

- 依赖引擎内部阈值 GC（否决：阈值上浮让它在常驻大堆上永不触发，正是耗尽 PSRAM 的根因）
- 帧间隙固定周期 JS_RunGC（曾短期上线后被本条取代：不看压力、稳态也在跑，垃圾仍可能积到最多一个周期）
- 修改上游引擎：去掉阈值上浮或提供宿主 GC API（暂缓：动快照与原生归档重建，收益与 PSP 既有宿主方案重合，等上游演进再对账）

## 影响

- 正面：稳态零 GC 开销，环垃圾存量上限一个步长；触发有 gc 对账日志与 60 秒 mem 诊断可观测。
- 实机验证：空闲 4 分钟 js_heap 走平、psram_free 波动 ±4 字节且零触发；27374 条配对切换灌注 150 秒零净增长；临时小步长验证版实测触发并回收。
- 代价：256 KiB 步长是写死的经验值；跌幅来自非 JS 分配时 GC 白跑一次（毫秒级）；步长内的环垃圾会短暂滞留。
- 与 0006 的关系：GC 与 eval 同在 owner task 执行才无并发问题，本条依赖 0006 的单任务承载约定。
