# 0024 — NS2 手柄广播采用持久唤醒形态与配对键语义

- 状态: active
- 日期: 2026-09-15
- 替代: 0023

## 背景

ADR 0023 留了一条未解项：开机自动回连不可靠——醒着的主机不主动接 0x00 回连广播，可靠入口只剩握把/顺序页。
对照分享资料与已验证参考实现可以看出，主机在非配对页面只认唤醒形态，0x00 回连形态是给真机抓包对账用的。

本条只取代 0023 的「广播状态位分离 + 唤醒突发」一项：连接间隔交给主机（主机下发 4 单位、控制器允许亚规范间隔）、输入被采用的门槛是 0x0c/0x04（DEV_READY 与休眠看门狗）、15 ms 上报节奏三条继续生效。

## 决策

已配对身份在未连接期间常驻唤醒广播（0x81 + 凭证里的主机地址），删除唤醒窗口与「窗口到点回落到 0x00 回连形态」的逻辑；未配对身份或配对流程期间发发现广播、流程之外静默，开机若当前形态从未配过任何主机则自动进入配对流程。配对页按钮改为真机配对键语义（先断开当前主机再进发现广播等新主机搜索），配对流程的自动退出判据是「当前形态每个身份都凭证在手且会话已注册」——主机真的配好并连上才收工；只看凭证会让已配对设备一按配对键就被判成完成、一秒内退回常态广播（配对键看起来毫无作用），只看连接则 JoyCon 组合会在只连上一只时提前退出。切换手柄类型/配色等价于旧手柄断电、新手柄上电：断开连接、按新身份重算配对状态与出厂块与广播拓扑，由断连回调按新身份恢复广播。JoyCon 组合未配对期间左右都收到 0x0c/0x04 后自动注入 L+R 120ms 并每 3 秒重试，已配对不再注入；L+R 与广播形态的判定都做成 ns2_adv 的纯函数并加主机端用例。串口 adv wake|reconnect 保留常态形态的实机 A/B 开关，wake 收敛为「断开当前链路让主机按唤醒广播重连」。

## 考虑的方案

- 保留 ADR 0023 的窗口方案（10 秒唤醒突发后退回 0x00 回连）：主机醒着时不采纳回连形态，用户仍需去主机配对页才能连上
- 把唤醒突发改成周期性脉冲（如每 30 秒发几秒 0x81）：待机主机被周期性叫醒，回连时机仍取决于脉冲与主机扫描窗口的重合
- 让设备以中心角色主动连接主机：与手柄的外设身份相悖，NS2 侧不接受控制器主动建链
- 未配对身份也常驻发现广播：与真机「没配对不广播、按下配对键才广播」不一致，任意扫描方都能看到设备

## 影响

- 实机验收：主机停在首页时设备上电即自动回连并可采用按键，主机待机时能被唤醒回连；
  副作用是设备通电且未连接时待机主机会被唤醒（0x81 常态的必然结果，已确认接受）。
- 配对新主机走配对页的配对键（等价真机按住配对键），日常连接不需要进配对页；
  已配对身份之间切换直接回连，切到未配对身份自动进配对流程（需在主机配对页配一次）。
- 回连形态与唤醒突发不再是常态，只作诊断开关保留；wake 语义收敛为断开重连。
