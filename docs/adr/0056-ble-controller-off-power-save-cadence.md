# 0056 — 静默时关闭 BLE 控制器并把节拍降到 12 fps 等效

- 状态: active
- 日期: 2026-09-24
- 替代: 无

## 背景

设备空闲（未连接主机、也没有广播窗口）时 BLE 控制器仍保持使能，控制器的事件间低功耗路径在 Kconfig 里没有打开，射频与 modem 持续通电；除屏幕背光外这是空闲发热与耗电最大的一项。
关栈与降节拍只应发生在真的没有链路可用的时候，也不能与刚被用户打开的广播窗口抢跑。

## 决策

完全静默（无连接、无广播窗口、不在配对流程）持续够久之后关闭整个 BLE 栈：停广播、停 host 事件循环、关闭并反初始化控制器，射频与 modem 断电。
连接键、HOME 唤醒与配对新主机在栈关着时只登记起栈意图，由控制面服务任务把栈带起来、在同步回调里按意图开窗，用户不必按第二次。
省电档判据只有一处：BLE 栈未运行。此时数据面采样与上报节拍、界面状态轮询与动画节拍一起降到 12 fps 等效，屏幕不熄灭，也不做空闲自动息屏。

## 考虑的方案

- 保持控制器常开、只停广播：空闲仍付射频电源域的电流，正是要解决的问题。
- 只打开控制器的事件间休眠：改动更小，但没有事件时控制器仍然通电，省下的只是事件间功耗，且与将来的电源管理组合需要额外验证。
- 静默时关闭整个栈（采纳）：射频与 modem 断电，代价是重新起栈要付一次控制器初始化与 GATT 重新注册的时间。
- 空闲自动息屏：本次不做，屏幕保持用户设定的亮度。

## 影响

- 空闲时只剩 CPU、PSRAM 与面板的静态耗电，发热明显下降；屏幕内容与交互方式不变。
- 省电档下采样、上报与屏幕操控都按 12 fps 等效节拍走：此时没有可上报的链路，调试注入与手柄驱动的界面操控会慢下来。
- 连接键到开始广播之间多出一次控制器初始化的时间，配对与回连时序需要真机复核。
- 起栈意图与关栈判据都收在会话层一处，数据面与界面只读省电档，避免两处节拍定义漂移。
