# 0012 — 固件在 PocketJS UI 就绪前自绘启动画面并提前点亮背光

- 状态: active
- 日期: 2026-09-13
- 替代: 无

## 背景

设备开机即进入 BLE 广播，主机侧秒级即可发现，但 PocketJS guest 的 mount/eval 需要十几秒（实机实测约 16 秒）；这段时间面板没有内容、背光保持熄灭，屏幕长时间全黑，用户无法判断设备是否正常工作。

## 决策

面板初始化完成后由固件自绘启动画面并按阶段推进进度：整帧铺满主题底色、几何手柄标记与进度条轨道后点亮背光，之后每个启动阶段只重画按键点与进度条两个小区域；UI 首帧提交成功后释放启动画面缓冲，画面交还 PocketJS 渲染路径；UI 初始化失败时进度条改错误色并留在屏上。

## 考虑的方案

- 固件自绘启动画面 + 阶段进度条（选定）
- 用独立动画任务持续刷新启动动画：显示更连续，但需要给 panel_transfer 增加互斥与移交协议，启动期并发风险上升
- 只提前点亮背光而不画内容：实现最小，加载期依旧是空白屏，用户仍看不出进度

## 影响

- 冷启动约 1.6 秒屏幕即有内容（此前要黑屏等到约 18 秒首帧就绪），加载期间有明确进度反馈，失败也能在屏上看出停在哪个阶段。面板所有权在启动期归固件、首帧后归 PocketJS，背光点亮时机从首帧提交提前到启动画面落屏。启动画面只占两块小缓冲、合计约 5 KB PSRAM（240×280 全屏缓冲约 131 KB，整帧提交后、guest 创建前即释放），不改动 owner task 模型、任务栈预算与渲染事务边界。代价是固件新增一份绘制代码与配色常量，需要与 ui/src/theme.ts 手工保持一致。
