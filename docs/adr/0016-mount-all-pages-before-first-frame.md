# 0016 — 首屏前一次性挂载全部页面，放弃首帧后逐帧补挂

- 状态: active
- 日期: 2026-09-13
- 替代: 0015

## 背景

ADR 0015 把首帧压到约 9.5 秒，代价是首帧之后还有 8-9 秒后台建树：期间每帧被阻塞 0.6-2.4 秒、UI 不刷新。实机使用中用户在这段时间切页或滚动会明显卡顿，观感比晚一点出现首屏更差。

## 决策

七个页面在首次渲染中一次挂完，首屏只在全部页面建树完成后提交，等待期由固件侧启动画面覆盖；切页仍翻转各页根节点的 hidden，App.tsx 不再有待挂队列，新增页面直接写在 JSX 里。

## 考虑的方案

- 一次性挂载全部页面（选定）：首屏推迟到 18 秒左右，但界面一出现即完整可用，切页与滚动不再被建树打断
- 首帧后逐帧补挂（ADR 0015）：首帧快，但首帧之后的建树期卡顿，实测不可接受
- 按需挂载 + 逐帧填充（ADR 0014）：除同样的卡顿外，首次进入每页还会看到半成品页面

## 影响

- 启动时序：guest eval 变长（含全部页面建树），启动画面的阶段权重按实测重新对齐；UI 首帧之后不再有阻塞帧
- 页面约定：页面根节点继续自行翻转 hidden，但不再需要向任何队列登记；DEFERRED_TABS 与 after() 补挂机制已删除
- 滚动范围：页面内容高度仍静态声明给 usePageScroll（框架不回读布局，ScrollerOptions.max 必须由调用方提供）
