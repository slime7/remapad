# 0002 — 引入统一硬件桥接协议与双工作区打包分层架构

- 状态: active
- 日期: 2026-09-03
- 替代: 无

## 背景

嵌入式UI系统需要在真机和PC仿真器中调用硬件外设，传统的紧耦合硬编码调用方式会导致前端无法独立调试，且固件与前端代码难以协同演进。

## 决策

借鉴PocketJS官方PSP示例项目的双向邮箱协议模型，建立前端bridge目录（protocol/driver/mock）与固件端bridge/drivers解耦目录，并在构建打包阶段由pocket.json驱动全量二进制封装与C头文件同步。

## 考虑的方案

- 采用类似pocket-youtube的协议与驱动分层，解耦前端与固件，PC端与真机走统一门面
- 在前端组件中直接侵入式调用宿主全局变量或直接绑定特定通信协议

## 影响

- 统一了软硬件调用契约并支持零刷机硬件模拟调试；需要维护TypeScript协议契约与C语言桥接派发逻辑的一致性。
