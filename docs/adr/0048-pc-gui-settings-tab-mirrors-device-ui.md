# 0048 — PC 图形界面新增设置页：镜像设备 UI 的可改项，调试动作只留命令

- 状态: active
- 日期: 2026-09-21
- 替代: 无

## 背景

图形界面 pc/remapadgui.py 原先只有「会话」「命令」「升级」三页，「会话」页把实机验收动作与调试动作混在同一张按钮表里。
设备上要改亮度、配色或 DS 行为只有屏幕一条路：屏幕不亮、排线松了，或者设备被当成桌面网关挂在机器上时，这些设置就改不了。
调试动作占着同一排按钮：连接键会拉起广播窗口、屏幕操控会把玩家输入收走，点错一次就得再点回来，而它们本质是排障时才用的动作。

## 决策

图形界面改成四页：会话、设置、命令、升级。
「设置」页把设备屏幕上的可改项搬到 PC——亮度与息屏、手柄配色（四款预设 + 四段自定义 0xRRGGBB）、DS4/DS5 的触摸板加减与截图键、重启与关机，另加只读的设备信息行。
设置页的读写都走固件 CLI（backlight / screen / ctrl / ds / reboot / poweroff），与屏幕改的是同一条持久化路径。
控件的当前值全部来自回读行（remapadctl.parse_device_reply 解析 status / version / ctrl / ds），
连接后自动读一次，「读取当前设置」按钮可随时重读，界面不自己记状态。
调试动作不再有独立按钮，只在「命令」页以「填进输入框、回车才发」的形式成组列出（连接键、屏幕操控、状态回读都在那里）。
设置页与命令页套滚动容器（CTkScrollableFrame）：窗口拉小后页面自己滚，不再靠调大窗口回避——
CustomTkinter 在页签里不会自己刷 scrollregion，界面按画布内容补上，滚轮与滚动条才真的能用。

## 考虑的方案

- 保留旧按钮表、把设置并进「会话」页（否决：一页里既有验收动作又有设置，误触的窗口没变小）
- 设置页直连 bridge 命令（否决：PC 侧没有 bridge 通道，桥接帧只承载输入报告、截图、OTA 与主机输出采集，低频控制面在 CLI）
- 界面自己记住设置值、不解析回读（否决：设备屏幕与串口都能改同一项设置，界面自算的状态会和真值分叉）
- 调试按钮改成二次确认（否决：调试动作本来就该低频，命令页已经够用，多一层确认只是噪音）

## 影响

- 正面：没有屏幕或屏幕不可用时也能改亮度、配色、DS 行为与电源；验收动作与设置各占一页，误触少了；设置值以固件回读为准，界面与设备不会分叉。
- 正面：回读解析与配色、时长这类纯函数进 pc/tests，接设备之前就能跑。
- 成本：界面多一个页签与一份设置同步代码；两个长页面各多一个滚动容器与一次滚动区域同步。
- 限制：设置能力仍受固件 CLI 约束（例如 USB 供电下关不掉机）；四条回读会各占一行串口输出，在日志区里看得到。
