# 0015 — 恢复首帧后逐帧补挂页面，放弃按需挂载与分帧填充

- 状态: active
- 日期: 2026-09-13
- 替代: 0014

## 背景

按需挂载（ADR 0014）把首帧压到 9.7 秒，但每次首次进入页面都要现场付一次整页建树：外层容器先出现、内容再逐块补齐，页面在数百毫秒里处于半成品状态，来回切页的观感明显变差，现场使用后判定不如启动阶段一次性挂完。

## 决策

恢复 ADR 0013 的机制：首帧只挂壳、状态栏、底栏与首页，其余 6 页在首帧之后由 after() 每帧补挂一页，切页时若目标页还没挂就立即补挂；删除 useMountCursor 分帧填充与首页加载提示，页面一次建树完成，切页只翻转 hidden。底部垫高交回 BottomPlaceholder 组件（BOTTOM_PAD_H = 120）。

## 考虑的方案

- 首帧后逐帧补挂（选定）：首帧最快，建树发生在启动阶段，用户切页时页面已就绪
- 按需挂载 + 逐帧填充（ADR 0014）：首帧同样快，但每次首次进入都看到半成品页面
- 全部页面首帧一次性挂载：首帧被推到 18 秒以上，不可接受
- 预建节点树但不设属性：属性设置只占约 1% 成本，收益可忽略

## 影响

- 切页即时，不再出现半成品过渡；页面根节点继续自行翻转 hidden，新增页面要在 App.tsx 的 DEFERRED_TABS 登记
- 代价是首帧之后仍有约 8-9 秒后台建树，期间每帧阻塞 0.6-2.4 秒、UI 不刷新；加载提示已按要求移除，用户看到的是静止画面
- 页面内容高度仍需静态估算传给 usePageScroll（框架不回读布局），估算误差由 BOTTOM_PAD_H 的兜底余量吸收
