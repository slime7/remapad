# 0052 — UI 帧节奏恢复 60 Hz

- 状态: active
- 日期: 2026-09-22
- 替代: 0037

## 背景

0037 把 UI 帧节奏降到 30 Hz，让每帧预算宽裕一倍，并把毫秒时长与帧数的换算收进 ui/src/tick.ts。
实机反馈相反：触摸手势的跟手与轮播结算的视觉衔接在 30 Hz 下发涩，触摸仲裁引入的延迟又被低帧率放大成可感知的滞后。
帧节奏由 host profile 的 tickHz 决定，跟手位移与动画都按帧推进，节奏一低这些交互的观感直接变差。

## 决策

tickHz 回到 60 Hz，host profile 与构建工具同步；轮播结算的倒计时改由 onFrame 帧计数驱动，四叶草背景补齐远左、远右连续条带消除结算时相邻页的边缘跳变。
CST816T 触摸改连续点模式（EnTouch|EnChange 等寄存器配置），去掉 0.5 秒手势仲裁延迟，60 Hz 下的跟手才真正生效。

## 考虑的方案

- 保持 30 Hz、只在交互上补帧：跟手与结算都要靠插值补，插值本身又变成新的重绘。
- 回到 60 Hz（采纳）：交互观感恢复，代价是每帧预算减半，重绘价格必须靠 damage 范围与绘制指令数压下来。
- 提高面板时钟换余量：面板已在 80 MHz 上限，没有余量可取。

## 影响

- 每帧预算 16.7 ms，重绘帧的价格只能靠 damage 范围与绘制指令数控制，局部重绘与重绘友好写法的权重因此上升。
- 触摸改连续点模式后，手势判定的延迟不再来自控制器，触摸帧与渲染节奏对齐。
- 部分取代 0037：tickHz 取值以 host profile 的 60 为准，0037 里「帧节奏写进 host profile、UI 侧以 tick.ts 为唯一换算来源」的做法继续生效。
