# 0049 — 固件侧 draw list 差分接管框架的整屏重画

- 状态: active
- 日期: 2026-09-22
- 替代: 无

## 背景

屏幕重绘的最小单位是行带，damage 计划由框架给出：它逐 op 对齐比较上一帧与本帧的 draw list，够用时不重画。
结构一变（切页、焦点环移动、弹窗开关、列表项增删）op 的数量或顺序就不一样，比对放弃并直接报整屏重画。
这类帧里真正变化的像素常常只占屏幕一小块，重画代价却按整屏算，60 Hz 的 tick 下就是连掉好几帧。
上游的 damage 比对与渲染器都在预置归档里，本仓库不持有可改的 Rust 源码。

## 决策

固件侧对上一帧与本帧的 draw list 做本机差分，把框架的整屏重画换成真实变化区域。
render_damage.c 解码 DrawList v1 每条 op 的字长与范围，先按逐 op 对齐找差异，落差对不齐时在重同步窗口内找落点，
只把差异 op 的范围交回渲染通路，区域上限与合并策略沿用框架。
接管条件严格受限：只在框架报整屏重画、上一帧成功提交、视口与光栅倍率及光栅资源版本一致、且本帧不是截图帧时生效。
任何一步失败（首帧、解码失败、窗口内找不到落点、区域超出渲染通路上限）都退回框架给的整屏计划。

## 考虑的方案

- 改上游 Rust 归档里的 damage 比对：归档是预置副本，改动要走 patches/ 的对账流程并重新构建 Xtensa 归档。
- 在 PC 侧算差分：draw list 只在设备上产生，传回 PC 再回传区域等于把每帧重绘做成一次往返。
- 用像素比对代替 op 比对：要先把整屏渲染出来才有像素，而渲染正是要省掉的那一步。
- 固件侧解 draw list 做差分（采纳）：纯 C 实现，无新依赖，失败路径天然退回框架计划。

## 影响

- 结构变化帧（切页、焦点环移动、弹窗开关）的重画范围从整屏降到内容框，稳态帧不受影响。
- 差分与框架的 damage 解码逐条对齐（范围取法、scissor 语义、区域合并上限），上游改 DrawList 布局时必须同步核对 render_damage.h 写下的契约。
- 上一帧副本占用一块 PSRAM，容量按界面 draw list 的字数留了数倍余量；超出容量即差分失败，该帧整屏重画。
- 串口新增 trace 与 drawlist 两条诊断命令：前者打印逐帧计划与逐条行带耗时，后者把本帧绘制指令原样转储给 PC 侧离线解码。
- 框架的整屏计划仍是兜底路径，差分只提供更小的候选区域，不参与渲染正确性判定。
