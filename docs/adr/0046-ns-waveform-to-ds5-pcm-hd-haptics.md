# 0046 — NS2 波形经布局映射重整为 DS5 的 PCM HD 触觉（USB 4ch 与蓝牙 0x32 双承载）

- 状态: active
- 日期: 2026-09-20
- 替代: 无

## 背景

NS2 的震动是波形描述而不是马达信号：每侧最多 3 个时序子帧、每帧一条低频音与一条高频音（9 位 log2 频率码 + 10 位/8 位线性振幅），按时间顺序各播一个等分周期，主机以接近输入上报的频率刷新它们来合成连续包络。
DualSense 的触觉音圈由音频级 PCM 驱动：USB 直插板卡走 4ch 48kHz 16-bit 的频道 3/4，蓝牙连 PC 时没有音频接口，只有 SAxense 逆向出的 0x32 私有触觉报告。
现有通路把三个子帧压成两带最大值再按 ERM 感知曲线重映射，时序纹理被压掉，映射规则也散在数据面而不是布局里。
LRA 参数包的位串按 BlueRetro 的 sw2.h 解释（真机验证过的参照）：低频频率 bit0-8、低频振幅 bit10-19、高频频率 bit20-28、
子帧使能 bit31、高频振幅独立 8 位——它的静止包常量 `0x1E100000`（高频频率 0x1E1、零振幅）与实机抓包的静止字一致，
实机主动子帧的使能位为 1；SDL_hidapi_switch2.c 的 `EncodeHDRumble`（10/10/10/10 对称位表）是没有上过真机的逆向猜测。
按更早的位表把频率位误读成振幅，「查找手柄」页才会观测到 1-2/255 的「载波电平」；静止包天然零振幅，载波电平阈值退居防线。
频率码是 log2 刻度、与 Joy-Con 一代 `log2(f/10)×32` 同一条曲线、4 倍细分：`f = 10×2^(码/128)` Hz，
9 位满量程 10-159Hz——BlueRetro 的驱动常量 `0x100`/`0x180` 在这条曲线上正好是整八度 40/80Hz，SDL 缺省码落在 44/83Hz 的经典低高对，
实机样例 `04 80 01 97 63` 解出「低频垫底 + 主震」的低频形态。

## 决策

映射在布局行内完成：`pad_output_layout_t` 新增 `hd` 规则块（承载采样率与 PCM 峰值、子帧周期、两带频率的落地范围与缺省值、采样强震段与发声段的频率）。
`pad_feedback_hd_render` 按它把主机的 3 个时序子帧按时间顺序重整成子帧序列：每个有效子帧各出一条低频音与一条高频音（无效子帧静默、保住主机排的节奏）、
振幅线性直迁（不做感知重映射）、频率解出 Hz 后按范围夹取回落（20-500Hz，码 0 回落缺省 80/135）；采样音色的「强震」段以 `hd.pulse_hz = 135Hz`
（音圈静置频率，≈共振点）铺到两侧音圈、「发声」段按音色表的段音高铺到扬声器并折进音圈（定位呼叫为两声上行短鸣 880/1175Hz，
近似 Joy-Con 提示音；起音/收音包络在合成端做，段边界硬切会听成咔哒）。
渲染结果随 FEEDBACK 帧扩到 57 字节下发，落地规则只在固件布局里有一份，PC 侧只做哑渲染：
USB 直插 PC 走 4ch WASAPI 流（频道 3/4 触觉音圈、频道 1/2 小喇叭发声，没有真正的声音时填充 0 静音）；
蓝牙连接 PC 走 `Ds5HapticsBt` 按 10.67ms 节拍发送 0x32 私有报告（142 字节 = 报文头 + packet 0x11 配置/序号 + packet 0x12 承载 64 字节
3000Hz 2ch 8-bit PCM + 种子 0xA2 的 CRC32 覆盖前 138 字节；对齐 SAxense.c 的真机互通布局——首版误写 141 字节、
CRC 错位且短覆盖 1 字节，蓝牙整路无输出）；蓝牙上没有扬声器通道，发声段折进两侧音圈——
两条承载通路对音圈的驱动完全一致，USB 的扬声器是额外加音；
两条通路都按子帧周期轮播、振荡器相位跨块跨子帧连续。
两条通路启用后都发 `haptic audio on`，`0x31`/`0x02` 的 HID 震动字节让位；USB 直插板卡仍走板上合成引擎（`haptic_synth` 按子帧时序轮播）。

## 考虑的方案

- 维持两带最大值 + 感知重映射、PC 侧自行解码原始参数包：映射规则散在固件与 PC 两处，时序纹理被压掉，ERM 曲线在音圈上过驱动低端。
- 固件把 PCM 流式送到 PC：串口带宽撑不住 48kHz 四声道，而 3kHz 的蓝牙私有流在 PC 侧合成已足够。
- 布局行 `hd` 规则 + 固件渲染 + PC 哑渲染（采纳）：落地规则只有一份，两条承载通路共享同一份子帧渲染结果，FEEDBACK 按长度与老 PC 兼容。
- 位串取 SDL 的 10/10/10/10 对称位表（曾在初期采纳后废弃）：频率位会错认成振幅、错认振幅刻度，也与实机静止字和主动子帧的使能位对不上；
  频率码按线性 Hz 直读同样被实机样例否定（码 4 解成 4Hz，log2 刻度下是「低频垫底」的 10Hz）。

## 影响

- FEEDBACK v3（57 字节）与老 PC 按长度兼容；等价判定按时序子帧量化值（振幅 16 档 / 频率 64 档）、有效子帧数与采样段边界投递，HD 流跟得上主机包络、低有效位不灌爆串口。
- 复合输出 `0x0016` 的震动段（填充字节 + 左右 LRA 参数包 + 命令帧）只在真的在震时解析成事件，静置零包不清掉 `0x0012` 的震动流。
- 蓝牙 0x32 的报文布局已对齐 SAxense.c（142 字节、CRC 覆盖 138 字节）；DualSense 蓝牙报告描述符
  （nondebug/dualsense 的实测 dump）对 0x32 正是这么声明的——141 字节数据（报告 ID + 137 报文体 + 4 CRC），
  同族 0x33-0x39 是逐步加挂 64 字节 PCM 块的更大形态，集合的 OutputReportByteLength 547 属于最大的 0x39。
  首版把 547 当成 0x32 的声明长度、写回前零填充，手柄对这种变长报文无反应——PC 现按 142 字节原始形态直写
  （Windows 接受按报告 ID 声明长度的短写，0x31 的 78 字节写法同理），实机确认 0x32 音圈触觉可达。
- 蓝牙喇叭真声走 0x36 报文（398 字节，DS5Dongle/vds 逆向，DualSenseClient 同源）：
  配置包 + 63 字节状态块 + 64 字节触觉 PCM + 200 字节 Opus 喇叭块 + CRC32，10ms 节拍；
  喇叭块是 48kHz 立体声 10ms 的 Opus CBR（码率 160kbit、VBR 关、complexity 0），PC 侧用 PyAV/libopus 编码
  （缺失时回落 0x32 音圈流）。状态块按 vds 的运行态改写：喇叭音量钉在 PS5 缺省档 100、
  **音频控制的输出路径位段钉在手柄喇叭（0x30，初始值是耳机/自动，不路由喇叭块会播进没插的耳机口）**、
  玩家灯与灯条字节清零（灯归 0x31 写回管）；配置包音频段全开（0xFF，vds 实发值）。
  蓝牙描述符声明 0x36 为 397 字节数据，写回同样是短写直达。蓝牙无线电是 2.4GHz 公共介质，
  常驻空包会和同频段设备互相干扰（实机：无线鼠标卡顿、触控板幻手势弹 OSK 与开始菜单、
  满速 0x36 ≈ 40KB/s 直接把链路灌断；vds 全速跑通靠自研 Linux 蓝牙驱动）——两条私有流都按内容门控：
  0x36 只在喇叭有内容（含收音尾 0.3s；采样按住期间不做满速保温——那会让按住期间 100% 空口、
  鼠标全程被骚扰，实机复测确认）时发送，触觉 0x32 静默超过 0.15s
  就整流停发，空闲一报不发（触觉块到手即播、无会话可保活）。发声段在 0x32 形态折进音圈（摸得到）、
  0x36 形态交真喇叭（听得到），两条形态的音圈触觉一致。
- 查找手柄的强震段在没有音频承载的写回通路上折进两侧马达（`pad_feedback_fold_pulse_motors`，
  取 max 不降档）：蓝牙没开私有触觉流、或音频端点开不起来时，定位呼叫至少摸得到——
  采样音色「不转马达」的规则只让位给真正接手发声的通路，而不是让采样整路消失。
  发声段仍然不驱动马达（声音归声音）。
- 手柄喇叭音量逐报钉在 PS5 缺省档（USB 0x02 的 b6、蓝牙 0x31 的 b8，valid_flag0 带 0x20 更新使能）：
  手柄自己的音量档被主机/PC 游戏压低时发声段会轻到听不见（实机：查找手柄短鸣非常轻）。
  DS5 布局行的 `amp_peak` 提到 30000（满量程的 91%）：音圈与喇叭的响度上限；游戏内振幅低
  （实抓中位 6/255）不受裁剪影响。
- 震动的起止过音圈包络门，板载合成（`haptic_synth`）与 PC 侧渲染同一条曲线
  （起音 1ms、收音 15ms、收音锁定最后发声的子帧淡出）：NS 震动的起止在承载上是块对齐硬切，
  只占一块的短震动会被截得几乎不剩、收震落点生硬——门控让短震动拉到可感知的长度、
  结尾平滑有界（长震动结尾多 15ms 感知不到）；门控只看参数级的有/无增益，
  子帧序列内部的静默切片原样保留（主机排的时间轴不变）。
  整段静默后的新震动从子帧 0 重播（不从上段震动的游标位置续播，起拍不落后）；
  蓝牙空闲整流停发的发送线程由 `set_params` 的新内容即时唤醒（启动不等 20ms 兜底轮询）。
- log2 频率刻度的基频（10Hz）与细分（128 码/八度）仍是待实机核对的假设——
  证据链（静止字、使能位、整八度驱动常量、实机样例形态）都指向它，但最终以真机听感为准；载波电平阈值退居防线。
