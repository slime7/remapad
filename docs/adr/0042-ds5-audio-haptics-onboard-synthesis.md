# 0042 — DualSense 触觉反馈走板上合成的音频通道

- 状态: active
- 日期: 2026-09-18
- 替代: 无

## 背景

DualSense 的 USB 音频接口后两路直连触觉音圈（PS5 同款用法，实机描述符已核对：UAC1 48kHz/16bit/4ch，等时 OUT 端点 MPS 392），NS2 的震动流却是分带 LRA 参数包；直插板卡时只走 HID 震动字节会把纹理信息全压掉。Registry 组件 usb_host_uac 面向通用 UAC 场景（麦克风、音量、多采样率），我们只需要一个固定格式的等时 OUT 流。

## 决策

在 usb/ 自写最小 UAC1 音频流客户端（usb_audio.c + 纯逻辑 usb_audio_parse.c）：只认 Type I PCM 4ch/16bit/48kHz，claim 音频流 OUT 接口后持续送板上合成的 PCM（haptic_synth.c，两带相位连续正弦 + 采样脉冲蜂鸣，扬声器两路恒零，每毫秒 384B、3 传输 × 4ms 排队）。布局行以 out.audio_haptic 声明能力；音频接手时数据面把 USB 路 HID 报告的震动字段清零，桥接路径照旧完整报告。

## 考虑的方案

- 引入 Registry 组件 usb_host_uac：通用能力用不上，麦克风/音量/多采样率是额外面，4ch 覆盖处于组件边缘
- 只走 HID 震动字节：零新代码，DS5 触觉表达力被压成两个振幅字节
- 自写最小 UAC1 等时 OUT 客户端（采纳）：约 700 行自包含代码，格式固定因此解析极小

## 影响

- 直插场景震动与采样退化升为真音频驱动（频率随参数包、相位连续）；等时流引入实时性依赖，3×4ms 排队容忍客户端任务调度延迟；桥接路径（PC 持有音频接口）不受影响；通道 3/4 与左右音圈的对应、10 位频率字段的单位是待实机核对的假设。
