# 0022 — OTA 升级复用桥接帧：双分区回写与回滚健康门槛

- 状态: active
- 日期: 2026-09-14
- 替代: 无

## 背景

设备已按 ADR 0009 固化 ota_0 / ota_1 双应用分区与 otadata，但没有升级通路：现场更新只能整片 USB 烧录，还得随镜像带上 bootloader 与分区表。唯一 Type-C 上的 USB-Serial/JTAG 已经承载固件日志、串口 CLI 与桥接输入帧，是唯一不必切换 USB mux 就能双向通信的链路；另一条 USB OTG 控制器与它互斥，切走会丢 COM 口，此时既无法烧录也拿不到日志。

## 决策

升级共用桥接帧：新增 OTA 帧类型 0x30 BEGIN / 0x31 DATA / 0x32 END / 0x33 ACK，解码器线格式上限由 72 放宽到 255 字节，报文帧仍按 72 字节校验。PC 端 pc/ota.py 按 16 帧窗口推送应用镜像（含内嵌 .pocket），设备侧 firmware/main/ota/ 把它写进 esp_ota_get_next_update_partition() 选出的非运行分区，esp_ota_end 校验通过后写启动分区并重启。开启 CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE：新镜像以「待验证」启动，UI 首帧成功且开机满 30 秒才标记有效，否则下次重启自动回退旧镜像。

## 考虑的方案

- 复用桥接帧并放宽解码上限（采用）：一条链路同时跑日志、CLI、输入与升级，PC 端工具复用免复位串口与帧编解码，设备不需要切换 USB mux。
- 在 BLE 上做 DFU：无需连线，但与 NS2 手柄模拟抢同一个 BLE 控制器，约 2.9 MB 镜像是分钟级传输，还要新增服务与续传状态机，且任何已配对主机都能触发升级。
- 走 Wi-Fi 无线升级：工程当前不使用 Wi-Fi，需要新增联网、配网与镜像服务器地址管理，超出设备形态。
- 另开一条大块传输协议：吞吐略高，但要在同一字节流上再放一套同步字与分帧，PC 端与固件都要多维护一套解析。

## 影响

- 正面：现场升级不再需要 USB 烧录，也不必带 bootloader 与分区表；升级期间设备照常作为手柄工作，NVS 设置与配对凭证不受影响；
  新镜像未过健康门槛时自动回退，断电与拔线只留下不会被启动的半镜像。
- 代价：升级需要 PC 有线连接且设备处于 COM 模式（host 模式或 OTG 切换后 COM 口不存在）；
  解码上限放宽后，误命中的同步字最多要让解码器多收 264 字节才靠 CRC 失败重新对齐；
  从 ota_1 启动后，开发期 app-flash 固定写 ota_0 会写错分区，需先执行 `idf.py erase-otadata`。
