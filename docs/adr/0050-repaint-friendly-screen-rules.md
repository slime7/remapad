# 0050 — 屏幕重绘友好的界面规则：带底色的圆角边框、瞬时切页加箭头提示

- 状态: active
- 日期: 2026-09-22
- 替代: 无

## 背景

S3 上每帧的重绘代价直接等于这帧碰了多少像素，而框架的 damage 是 op 级的：一条指令的范围变了，它覆盖的整块矩形都要重画。
界面上几种观感相同、写法不同的东西，在这套模型下代价差出许多倍：圆角元素只描边框不给底色，退化成逐行覆盖条，一个小圆环就撒出两百来条矩形指令；
切页时搬动整页内容，每帧都要重画整个内容框，动画越久越贵。用户看到的是切页慢、拖动卡，而开销完全由界面写法决定。

## 决策

屏幕上的「动效」按重绘友好来选，两条规则写进界面：
1. 圆角 + 边框的元素必须同时给出底色，底色取它所在面的颜色，让引擎走「两枚圆角填充」的快路径，而不是逐行覆盖条。
2. 切页瞬时完成，方向提示交给行进侧的翻页箭头弹一下；只有拖动预览保留跟手平移，因为那是手指驱动的直接反馈。

## 考虑的方案

- 保留整页进场的滑动动画：每帧重画内容框，在这块屏的渲染能力下动画本身就只剩每秒十几帧，看起来是跳帧而不是滑动。
- 用透明度交叉淡入：逐像素混合是这条通路上最贵的操作，整页混合一帧就是整屏代价。
- 用放大进场：改几何尺寸会改绘制 op 的构成，一帧就要重画整张卡片。
- 瞬时切页 + 箭头方向提示（采纳）：切页只剩一次内容框重画，提示本身只有 32 × 32。

## 影响

- 切页与拖动回弹的重画代价从「几帧整页」降到「一次内容框」；页面没有进场动画，箭头弹动是唯一的动效。
- 新增可点控件、选中指示环时按第一条规则写：圆角加边框的写法必须配底色，否则一次就撒出上百条矩形指令，还会把该帧的 damage 比对拖成整屏重画。
- 切页的方向提示落在翻页箭头上，箭头同时仍是触摸切页区；改动箭头位置或大小要一并确认提示仍然可见。
- 拖动预览仍是每帧重画内容框，手指移动多快就重画多快；要再降只能连跟手平移一起换掉。
- op 级差分吃不到「真实变化的像素比 op 覆盖的矩形少」这部分，像素级差分要先渲染才有像素，不成立。
