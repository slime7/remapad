# 0059 — 不实现 USB 有线手柄输出

- 状态: active
- 日期: 2026-09-30
- 替代: 无

## 背景

协议文档覆盖了真机 USB 形态的完整规范（复合接口描述符、Report 0x05、USB 指令形态），功能缺口盘点曾把它列为资料齐全、可实现的扩展方向。
评审否决：设备唯一的 Type-C 已承担供电、输入接收（host 直插）与升级调试（USB-Serial/JTAG），主机侧 BLE 已覆盖主要使用场景，有线输出的场景与收益不足。
ADR 0039 已把对外身份收敛为 BLE 单身份 Pro Controller 2，本决策把传输形态的边界一并固定。

## 决策

设备输出通路只保留 BLE（Pro Controller 2 形态），不引入 USB device 手柄栈，不提供插主机或底座的有线输出模式。
USB 硬件接口只用于输入侧直插与升级调试；协议文档的 USB 形态规范仅作协议记录。

## 考虑的方案

- 维持 BLE 单一输出通路（采纳）
- 增设 USB device 手柄角色、复用 pad_target_t 增加 USB 传输（否决：无实用性，占用唯一 Type-C，还需另起一套设备协议栈）

## 影响

- 正面：输出形态边界固定，后续功能盘点不再重提有线输出方向。
- 代价：插底座或有线连接主机的场景不覆盖；将来若重新评估，需另立 ADR。
